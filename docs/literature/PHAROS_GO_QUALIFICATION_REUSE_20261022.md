# GO qualification beyond the Pharos view: feasibility and reuse

October 22, 2026. **Source preparation only. No INMC outcome values, binary labels,
predictions or model features were read or generated. No Brev compute was used.**

## Verified gap and candidate decision

Qualified GOA annotations are useful for source inspection and a future
qualification/update comparison. After the completed cross-source audit below,
the next selected learning intervention is narrower: add GO's term hierarchy to
the same restricted Pharos annotation substrate. The full experiment is not
frozen, and neither intervention is a validated correction to Pharos or a
demonstrated prediction improvement.

The inspected [Pharos schema](https://raw.githubusercontent.com/ncats/pharos-graphql-server/master/src/schema.graphql)
exposes GO identifier, aspect, term, evidence/ECO, assigning source and
`explanation`. The saved official implementation at
`runs/pharos_coverage_20261014/TCRD.js:498–535` computes `explanation` from an
evidence-code lookup. It supplies the meaning of IPI/IDA/etc., not the source
annotation's negation, reference or biological context. Our existing retrieval
therefore cannot recover those missing fields by selecting `explanation`.

The [historical TCRD UniProt loader](https://github.com/unmtransinfo/TCRD/blob/90d072154fa7afa1eca3dc3449dae709c72cf1b6/loaders/load-UniProt.py#L285)
reads GO cross-references from UniProt XML, retaining those five source fields.
Its configured inputs are from 2020, so it does not establish the deployed 319
loader/version. The inspected query has no explicit NOT filter, but upstream
selection remains unverified. **Missing qualifier fields are not proof that
negative annotations were loaded and lost, or that a Pharos annotation is wrong.**

[GAF 2.2](https://geneontology.org/docs/go-annotation-file-gaf-format-2.2/)
already represents relation/NOT, reference, With/From, taxon, annotation date,
assigning group, annotation extension and product form. The remedy is to reuse
that published representation and parser. A matched-looking row is additional
detail from overlapping evidence, not an independent experiment.

## Release boundary: 319 is not 400

The live GraphQL metadata query returned `pharos319`. Its unfiltered
`dataVersions` returned Expression, GTEx, JensenLab textmining mentions, NCBI
and Uberon; **no GO release/date was returned**. The saved official `VersionInfo`
implementation queries all `input_version` records when keys are omitted. No
GO vintage can be inferred from those other sources' dates or the database name.

The [NCATS public directory](https://opendata.ncats.nih.gov/public/pharos/)
exposes Pharos400 canonical and full TDL/identity tables. They contain summaries
and counts, not complete GO/PPI/pathway records. The verified
[archive directory](https://opendata.ncats.nih.gov/public/pharos/archive/)
lists full SQL dumps through 319. [400 release notes](https://opendata.ncats.nih.gov/public/pharos/pharos400_readme.html)
document changed protein grouping and identifier treatment. Reconcile these
separately; a release/accession update is not evidence of Steward's enrichment
value. The API-versus-release deployment difference remains unexplained.

GO data are [CC BY 4.0](https://geneontology.org/docs/go-citation-policy/), also

remain unchanged; the wrapper is not a replacement GAF parser or annotation
validator.

## Outcome-blind source inventory

[`audit_go_qualification.py`](../../scripts/audit_go_qualification.py) scanned
910,476 source rows and staged 131,860 human annotations for **1,790 of 1,797**
requested accessions. The seven without an exact annotation stay in the
inventory. Subject taxon must be human; the second interacting taxon does not
change subject identity. No isoform suffix is silently collapsed.

The staged rows include 143 NOT annotations, 3,766 nonempty extensions and
80,432 IPI annotations. 30,628 rows name another inventory accession in With/From;
this is a risk inventory, not an assertion that these are held-out pairs.
All staged rows have a nonempty product-form field; this does not mean all are
isoform-specific. No staged row cites `PMID:36949045` directly. That narrow check
**does not establish freedom from study overlap or derived evidence**.

Twenty-three synthetic boundary tests pass, including complete parser paths with
and without a Pharos join and an integration test consuming the independent
inventory audit's actual generated report (`input_files`, not an invented
`files` field). Only the parser integration test requires the optional pinned
Biopython environment; core tests run the other 22 checks and skip that one when
Biopython 1.88 is unavailable. The real source-only run executed the pinned upstream
parser successfully. These results establish ingestion/preservation behavior,
not scientific correctness. Source-only receipts are preserved in `source_audit/`
and `source_audit_v2/`; their recorded script hashes identify the earlier versions.
The subsequent `pharos_join/` run completed both comparisons against the exact
completed Pharos retrieval. See the [uniform-source report](../evaluations/INMC_PHAROS_UNIFORM_20261022.md)
and its tracked summary for the immutable bindings and counts.

## What matching can establish

The compatible projection is `(accession, GO ID, evidence code, assigned_by)`.
Compare only accessions present in the supplied completed Pharos chunks and
retain both source row sets. Report one-to-one projection groups, multiple-record
groups, GOA-only groups and Pharos-only groups separately. Even a unique match
does not establish identical source records: Pharos omits the reference, date,
relation and product form that distinguish them.

The join reuses the independent inventory audit's `verified_header` and
`verified_chunk` checks. All chunks must be the exact manifest of one completed
retrieval, bound to the same inventory bytes and population, plan, endpoint and
Pharos version. Partial or mixed retrievals and unrelated target identities are
rejected before parsing the GAF. The output records the validated retrieval
plan/summary, source and chunk file hashes, and validator implementation hashes.

The projection summary stratifies GOA rows, NOT rows, extension rows, blocked
references and reserved-pair diagnostic hits by those groups. A current NOT row
in even a one-to-one group can reflect a changed annotation or a different
underlying source record; it is not automatically a recovered Pharos error.

GOA-only groups may reflect release changes, source/filter differences or mapping
changes. They cannot be called newly discovered biology. With no verified Pharos
GO vintage, importing current annotations mixes qualification with update effects.
A same-GOA-release projection-versus-qualified comparison would be needed to
isolate the representation contribution; that comparison is not frozen here.

## Confounding and remaining freeze criteria

[Gillis and Pavlidis (2013)](https://doi.org/10.1093/bioinformatics/bts727)
document shared sources between GO annotations and PPI networks. The GAF
specification explicitly allows IPI With/From to identify the interacting protein.
Deleting a test graph edge alone cannot remove this exposure; dropping only IPI
also cannot prove independence of other annotations.

The optional `--pair-mask` reads the already-audited `overlaps.json`, verifies its
sealed sibling `report.json`, the overlaps content digest and the exact accession
inventory hash. The report's retrieval plan, summary, source version and saved
file hashes must also match the supplied Pharos retrieval; a mask from another
retrieval is rejected even if its accession inventory is identical. Pair-mask
auditing therefore requires `--pharos-chunks`; source-only auditing without a
mask remains available. It checks every focal-product/With-From product against the
reserved unordered equivalents, including reverse and self-equivalent pairs.
Literal UniProtKB references in annotation extensions are scanned separately.
Other namespaces, unresolved forms and unknown extension content remain visible;
regex candidates do not establish extension semantics or a complete leakage mask.
No feature gate, label table or graph pruning is implemented by this audit.

Before using these records for learning, define source/annotation and
product-equivalence masks using the completed comparison and inspect
references/With/From/extensions against **all** reserved and development pairs.
Keep unrelated-source coverage and outcome eligibility separate. Freeze the
source release, admissible relations, graph projection, comparison controls and
learner budget before decoding outcomes. Preserve unknown provenance and failed
matches. Predictive gain remains a hypothesis.

## Selected next comparison: ontology structure with unchanged annotations

The completed join contains 5,817 one-to-one compatible projection groups, 798
multiple-record groups, 35,865 GOA-only groups and 16,668 Pharos-only groups.
It flags 955 With/From rows and ten extension rows with literal reserved-pair
equivalents. Of these, 747 With/From and six extension rows include a
self-equivalent product pair; these must not be described as 955 independent
off-diagonal interaction claims. Generic With/From roles and reference semantics
still require interpretation. This is not a ready-to-import independent evidence
set.

For a simpler first intervention, keep the same protein annotations and add
only the official GO term-to-parent `is_a` graph. This tests added ontology
structure without adding current-GOA protein labels. It does not isolate every
ontology-vintage effect or validate missing qualifiers.

[Zhong and Rajapakse (2020)](https://link.springer.com/article/10.1186/s12859-020-03816-8)
combine GO term relationships and protein annotations for PPI prediction. Their
GOA2Vec method uses node2vec and STRING-derived tasks, including artificial edge
removal/addition. That is methodological support for the graph representation,
not an independent experimental reference or a reproduction of our R-GCN/INMC
design. No GOA2Vec code or pretrained embedding is imported.

The selected initial scope is cellular-component annotations with IDA/HDA
evidence, excluding `GO:0032991` (protein-containing complex) and its `is_a`
subclasses. [GO's evidence guide](https://geneontology.org/docs/guide-go-evidence-codes/)
supports the direct-assay interpretation; it does not certify annotation
correctness or source independence. This restriction is our prespecified task
adaptation to reduce use of interaction/complex-derived information, not a
published quality ranking. Retain Pharos's unknown relation/polarity status.

An outcome-blind check of the pinned ontology and retrieved rows found **2,607
distinct product–GO pairs across 995 products and 211 direct terms** in this
scope, after excluding 31 obsolete terms affecting 194 rows. The `is_a` ancestor
closure contains **285 nodes and 319 edges**. The larger original Pharos GO set
contains 566 currently obsolete terms affecting 1,947 rows. Keep those source
records in the audit, but do not invent replacements or include them in only
one comparison arm. The actual frozen graph builder must reproduce these counts.
The outcome-blind probe and exact library/source hashes are preserved locally in
`runs/inmc_go_feasibility_20261022/hierarchy_scope/` and bound by the
[tracked preparation receipt](../evaluations/inmc_pharos_uniform_20261022_summary.json).
That source-count probe creates no graph features or predictions.

Reuse standard JSON parsing of the official [OBO Graphs format](https://github.com/geneontology/obographs)
and the already installed NetworkX 3.7 for DAG checks and reachability. Stored
`is_a` edges point from child to parent: NetworkX `descendants(term)` therefore
finds ontology ancestors, while `ancestors(complex_root)` finds subclasses.
[GO relation guidance](https://geneontology.org/docs/ontology-relations/) explains
why relation types must not be conflated. This initial intervention excludes
other relation types and does not infer positive gene-function assertions.

Use paired R-GCN arms with the same HuRI supervision, gene–product mappings,
restricted Pharos annotations and union vocabulary; add only the 319 ontology
edges to the enriched arm. Retain scaffold-only R-GCN and ComplEx controls.
All original genes/candidates remain, including those outside this annotation
scope. Call this a **restricted Pharos-context comparison**, not a full-Pharos
evaluation or a CRC therapy benchmark.

Before the full freeze, validate the gene→product→GO→parent propagation path
in the native model, build and audit both projections, apply all source/pair
exclusions, and fix development selection and model/update budgets. Three edges
separate a scored gene from a parent term; a one- or two-layer message-passing
configuration does not directly expose the new parent context to that gene.
The existing one-layer synthetic smoke did not test this proposed architecture.
No panel outcomes or biological models were used to select this scope.

hashes and source audit are in `runs/inmc_go_feasibility_20261022/` (ignored).

  --gaf runs/inmc_go_feasibility_20261022/HUMAN-uniprot.gaf.gz \
  --inventory runs/inmc_mapping_followup_20261022/input_audit_v2/context_targets.json \

Use a new output directory. The optional `--pharos-chunks` accepts the `chunks/`
directory of one completed, inventory-bound retrieval, alongside its original
plan, source, summary and inventory files; it does not interpret outcome files or
create graph features. Pass the independent coverage audit's `overlaps.json`
with `--pair-mask` when it is ready; the tool verifies the same-retrieval bindings before
using that identity-only mask. Leave the source-only receipts unchanged.
