# Graph selection and evidence review delivery

The interface makes two existing operations visible: selecting one result's
diagram and recording a source review as a new run. Expanding summary text does
not change the graph. **Show in graph** selects the result and returns focus to
its diagram. The readable source guide exposes **Record evidence review** in
an editable ordinary workspace.

**Save review in a new run** uses the existing review backend. A real browser
check saved one provisional demonstration review in an isolated APP/PSEN copy,
reopened the result and verified native-source replay. All 58 original source
files stayed identical. No assertion was accepted. Public, exported and applied
retained views remain read-only. The shared site does not acquire write access.

The complete APP/PSEN package includes an optional local launcher. Its source,
question, recorded agent and review files retain their original bytes. Only the
three UI files differ in the core runtime. Python source adapters, review
backend and agent controller are unchanged. The report and narrated demo explain
how to save a personal reviewed copy while preserving the original.

The public backend also uses a 3 GiB memory limit on its existing EC2 host.
The measured 2.08 GiB peak explains the earlier 2 GiB limit failures. Source and
saved-answer hashes match the original service. The private service, gateway,
Neptune and access controls remain unchanged. No new cloud resource was created.

The small package contains project presentation/software materials and a CC0
Reactome inspection annex. The four full mixed-source graph/example archives
remain separate handoff files under their source terms. No public bucket,
source-archive publication or organizer submission was performed.

This increment adds no scientific measurement, model request or source
retrieval. Previous scientific comparisons and unsuccessful experiments remain
unchanged. These are functional checks rather than an independent usability
study or biological validation.
