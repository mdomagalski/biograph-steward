## Priorities through submission

1. Give reviewers the existing HTTPS example and token privately. Ask them to
   find the answer, identify what a source actually supports, and explain how
   the workspace export differs from the answer diagram. Collect broken
   links, unclear terms and misleading inferences before feature suggestions.
2. Address observed access/explanation problems and designate the release
   checkpoint. Keep software, hosted runtime, research and mixed-source packets
   clearly named; a new local study does not update the hosted app.
3. Complete the intended public MIT repository/release on the submission date,
   attaching tested code and permitted aggregate material. Keep tokens and
   uncleared mixed-source data outside the public release. The existing graph
   download and separately authorized source access are distinct routes.
4. Submit the resulting scoped graph, the complete decision ledger and the
   preserved retrieved baseline through the permitted route. Retain their
   exact identities and any unresolved source terms. Mixed-source KEGG
   redistribution has not been cleared by this audit.

No additional cloud service, NemoClaw deployment, paid literature API or new
uncontrolled model sweep is needed to complete this handoff. Brev is unnecessary
for saved review; keep the AWS reviewer service available for the team.
