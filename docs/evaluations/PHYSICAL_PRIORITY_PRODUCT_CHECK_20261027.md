# Optional physical association priority: product verification

October 27, 2026. The existing guided protein-neighborhood form now offers
optional native STRING 12.5 physical association priority. Alphabetical order
remains the default. This increment applies the completed source-component
investigation to the product; it does not reopen that benchmark or claim a new
biological accuracy result.

## Real saved Pharos question

The check used BRAF (`UniProtKB:P15056`) in
`crc_civic_final_20261015`: a saved 99-target Pharos319 colorectal-cancer cohort.
Only reported interaction paths were selected, in candidate exploration mode,
with a 30-protein result limit. All 21 matches fit within that limit. The
historical Pharos graph was retained; current STRING scores were saved as a
separate question supplement.

Three source requests completed in three attempts: the pinned release check,
exact-accession mapping, and typed functional network with physical overlay.
Fourteen matches had native numeric physical scores. Seven had no physical
overlay under this profile and remained explicitly unranked, after scored
matches. Every mapped pair had a functional row.

This is an ordering demonstration, not an expert judgment that these rows are
correct, direct-binding interactions or disease-specific mechanisms. STRING is
already a Pharos provider. A native physical score is not independent evidence.

## Verified preservation and replay

- All 21 matching proteins, evidence paths, assertion identities, source records
  and local review states agree between the two orders. Display-local citation
  aliases may change with result order; their assertion bindings remain equal.
- Every file in the original source run has the same hash before and after.
- Offline answer reconstruction is exactly equal using the saved source packet,
  with live collection disabled.
- HTTP reopening and ZIP download reproduce the saved answer and source files.
  The ZIP includes the complete ordered population, explicit missingness, raw
  response text and request receipts, summary, paths and readable report.
- The served HTML contains exactly one ranking selector inside the existing
  question form; this increment adds no new top-level panel.

Focused software checks passed: 50 Python question/cohort/transport checks,
16 HTTP checks, and 21 JavaScript state checks. These cover ordering before
limits, default compatibility, zero and missing scores, complete candidate
binding, rate control across concurrent and successive questions, failure
without fallback, source/review changes and modified export rejection.
JavaScript syntax and whitespace checks passed.

A live visual/browser walkthrough could not be completed: the browser skill's
bundled native component was rejected by macOS, and the alternate native
connection also failed to start. HTTP and JavaScript state verification do not
substitute for a visual or independent user walkthrough. No Brev, model or GPU
was used. The four reserved IntAct study bodies remain unopened.
