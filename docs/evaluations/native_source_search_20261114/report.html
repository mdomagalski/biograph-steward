Same 24 development questions · original and corrected runs preserved

Correcting abstract transport improved the handoff, but direct PubMed search remained stronger.

The unchanged native-tool profile was repeated once after a verified Mac system-proxy failure. All 12 requested abstracts then resolved and all 12 valid final lists were nonempty. Final reference-paper recall was 4.17%; retained JSON recall was 6.25%, and deterministic PubMed search was 17.26%.

No agent adoption or scientific-accuracy claim. The paired interval against the retained JSON agent included zero; the interval against direct search favored direct search. The original 0% proxy-confounded run remains intact. This repeat used already exposed questions and references, so it is development evidence.

What the targeted repair changed

Nine fresh abstract fetches in the original run were unavailable. A paired probe of one record identified default macOS system-proxy refusal; the same record succeeded with normal TLS through a direct opener and then through the unchanged project fetcher with per-process NO_PROXY=* and no_proxy=*. The probe did not establish every original error’s cause.

The one repeat changed only that process environment and used a separately named cache. All successful original captures were copied byte-for-byte by a fixed all-tools status rule; unavailable/partial captures stayed in the original cache. Model, prompts, native API policy, budgets, all 24 questions and controls were unchanged. All 122 original cache entries (329 files) were independently rehashed unchanged; all 309 seeded files remained ordinary byte copies.

In the corrected run, 12/12 requested abstracts had exact identities and nonempty abstracts: nine fresh fetches and three cache hits. This closes the observed abstract-availability gap for this repeat, without showing that all remaining retrieval loss has one cause.

Remaining limitations are visible

Twelve cases still failed at the API/parser handoff: ten auto decisions returned no accepted tool call and two returned an empty provider-parsed call list. No output-cap guard fired. Discarded model bodies were not inspected or reconstructed, so the exact model-versus-parser cause remains unknown. The corrected run used 82 generation requests and 82 tokenizer requests, with 8,473 completion tokens. It suppressed 92 additional provider-parsed entries without executing them.

All 24 cases had candidate papers. Five pools contained 11 listed reference-paper pairs; one pair survived into a corrected final list. Three reference-containing cases still failed before a final, and one nonempty final selected other candidates. Pool union coverage uses up to 20 candidates and is a post-hoc error-localization diagnostic, not a new top-10 method or a demonstrated fallback.

  • Original public BioASQ 11 data, DOI 10.5281/zenodo.7655130, CC-BY-2.5; the same 12 factoid and 12 list questions previously consumed during development. Positive document lists are incomplete: an unlisted paper is not shown irrelevant or false. Model-training overlap is unaudited.

  • Existing Nano8B revision 54641c… and vLLM 0.8.5 V0. A published first-entry API policy handles the old runtime’s ignored nonparallel flag. Standard named finish is used only in finish-only states; all actual generated usage and suppressed-entry counts remain recorded.
  • At most four model decisions, 1,200 output tokens per decision, two actual searches, one abstract request and ten unique final candidate IDs. No further prompt, model, query or strategy sweep followed this targeted transport repair.
  • The full protocol/controller profile was compared; this is not a pure formatting causal ablation, scientific entailment test, independent Pharos evidence assessment or whole-graph accuracy estimate.
  • All 24 guards and 2,000 resamples were independently checked; largest numerical difference was below 2 × 10−17. Deterministic PubMed search remains the maintained default.
