# Continue from the hosted KRAS graph

The native KRAS example offers **Download an editable local copy** beside its
read-only notice and under **Export**. The ZIP contains the portable app, the
same full source workspace for 99 primary targets, all attached source files, the saved KRAS
question and its actual recorded Nemotron investigation. It preserves the
9,724-entity graph and 19,310 evidence records. This is the full workspace rather
than only the smaller diagram for one answer.

Extract the ZIP into a new folder. With Python 3.10 or newer, run
`python3 START_EDITABLE_LOCAL.py`. The launcher chooses an available port on
your computer and opens the workspace. Saved inspection and review require no
model, GPU, AWS account, access token, package installation or fresh retrieval.
Keep the terminal open. Source checks on first opening can take some time.

Under **Inspect sources**, select a claim and choose **Record evidence review**.
Enter a reviewer, decision and reason, then **Save review in a new run**. The
app opens the reviewed workspace and links to the preserved original. A review
records an evidence judgment and its history. It does not provide a general
node-and-edge drawing editor or assign an independent scientific truth label.

The public example and the applied retained-graph example stay read-only.
Other hosted workspaces, cloud assessment pages, optional global GO/QC source
files and the Neptune mirror have separate scopes. Original source terms and
attribution travel with the copy. The MIT software license does not relicense
the upstream data.

## Verification

The prepared archive contains 413 files and is 106,909,889 bytes. Every member
passed CRC and SHA256 verification. Its `WORKSPACE_FILES.json` pins all original
workspace, question and job files. A fresh extraction imported the packaged
runtime and replayed the complete sources, question and recorded agent with
network sockets blocked.

An actual browser check then saved one **provisional** demonstration review for
KRAS–CDC42BPB in a new run. Full source replay and HTTP reopening passed. All
207 original workspace files remained byte-identical. Native source profile
pins were preserved, and the accepted assertion count remained zero. This
increment makes no new model calls, source retrieval or biological measurement.

The managed Chrome profile used for capture displayed the new control but
blocked its ZIP transfer with **Blocked by your organization**. No browser
policy was overridden. The earlier independent anonymous HTTPS check verified
the complete archive's bytes and checksum. The byte-identical locally prepared
archive supplied the isolated launch and review check described above. These
are separate observations, rather than a claim of a completed Chrome transfer.

The implementation reuses the existing source-release packager, saved-question
and recorded-agent verifiers, and new-run review API. A prepared, registered
archive is streamed in bounded blocks rather than built or buffered for every
public request. Download metadata binds it to the exact source manifest, graph,
snapshot and question. The gateway exposes only the registered GET/HEAD routes.
